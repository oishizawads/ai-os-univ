# Meta-OS Map — どう回すか

> `CAPABILITY_MAP.md`（何をやるか＝22領域）の対。こちらは**AIと全業務を回す運用OS**。
> 8層パイプライン＋横断。各層: 採用した型 / 出典 / 適用法 / 状態。
> 思考法は `ai-os/knowledge/frameworks/` にカード化、ツールは install。出典は検証済みのみ採用。
>
> **起点**: 全タスクは CLAUDE.md のトリアージで一度この8層に位置づけられる（軽い一拍＝位置づけ＋stop adding）。重い/不可逆/分析/納品のときだけ該当層を深掘りする。

8つの観点（矢印は標準的な流れの目安。順序固定ではなく、必要な層へ行き来・再入する）: **集める → 考える → 決める → 動かす → 検証 → 伝える → 残す → 改善** ＋ 横断(経済性 / 倫理・法務)

---

## ① 集める（タスク入力の収集）
このタスクの判断・実装に必要な入力・制約・前提が**不足している時だけ**集める（足りているなら飛ばす）。何が揃えば足りるかを先に定義し、過剰収集を止める（Satisficing＝③と接続）。
- 対象: データ／仕様／既存コード・notes（`SESSION_NOTES.md` 等）／制約（締切・PII・ライセンス）。
- 「集めること」自体が目的化したら止める。継続的な地力上げは番号外の **継続トラック：能力開発** へ（①はタスク入力に限定）。

## ② 考える（思考フレームワーク）
✅既存（`ai-os/knowledge/frameworks/`）。ピラミッド/MECE/イシュー駆動/システム思考/仮説思考。
- 追加採用: **Cynefin**（明白/煩雑/複雑/混沌でMLが適切か判断 → `business_frameworks/contextual_decision_cynefin.md`）、**Thinking in Bets**（確率で判断・記録）。

## ③ 決める（意思決定・トリアージ）★過密バイアス対策
- **Two-way door**（Bezos 2015株主書簡）— 可逆な決定は速く・不可逆だけ慎重。**既にこのworkspace運用で実践中**。
- **Hell yes, or no**（Derek Sivers）— "たぶんYes"は全部No。機会費用フィルタ。
- **Satisficing**（Herbert Simon 1956）— 最適でなく"十分条件"を先に決めてスコープ肥大を止める。
- **WSJF**（SAFe）— 遅延コスト÷ジョブサイズで定量順位付け。複数クライアント並行時。
- **Pre-mortem**（Klein, HBR 2007）— 開始前に「失敗したとしたら理由は」を洗い出す。
- **判断余力の安全弁** — ユーザーまたは第三者から疲労・眠気・判断不安が明示された場合、重い・不可逆な決定は保留し、可逆な縮小または独立確認へ切り替える。時刻だけでは判定しない。

## ④ 動かす（AI運用・トークン）
✅既存（既定はClaude直接実行。委譲 /opencode-coder 等は任意のescape hatch＝ユーザーが振った時に発火。RTK・/orchestrate系は廃止）。
- 内面化: **Context Engineering**（見せるタイミングの設計）、**Progressive Disclosure**（必要粒度だけ段階供給＝品質層スキルで実装済み）、**Prompt Caching**（API直叩き時・静的部分をキャッシュ）。
- **人間の実行** — AI運用に限らず、自分で実装・交渉・実験することも④に含む。

## ⑤ 検証（AI出力を体系的に信用する）★最重要の穴
- **LLM-as-Judge**（arxiv 2306.05685, Zheng+ NeurIPS2023）— 強モデルを審査員に。人手評価なしで採点。
- **2経路突き合わせ** — 同じ問いを独立2経路（モデルA/B、LLM/検索）で処理し矛盾検出。低コスト・ハルシ検出に直結。CLAUDE.mdの"単一経路を信用するな"の運用版。
- **Constitutional AI 自己批判**（arxiv 2212.08073, Anthropic）— 原則リストを当てて自己修正。
- ツール: **deepeval**（pytest風・LLMシステム単位評価／LICENSE要確認）、**ragas**（RAG専用）。LLMをパイプラインに入れた段階で導入。

## ⑥ 伝える（統合・説得）✅FDE/クライアント業務の核
- **Storytelling with Data**（Knaflic 2015）— 「何を決めてもらうか」から逆算する可視化。
- **Assertion-Evidence**（Alley）— スライドタイトルを主張文に。`slides-maker`の「アクションタイトル」と同じ＝既存。
- **"So what?" ドリル** — 各記述に「だから?」。行動に繋がらない文を削る（ピラミッドの延長）。
- **データインク比**（Tufte 1983）— 装飾/不要グリッドを削る。`viz-style`の理論的裏付け。
- 把握: **Amazon 6-pager**（Working Backwards）— 重要提案をナラティブ文書に。導入コスト高。
- **早く小さく伝える** — 最終報告を待たず、途中で方向をすり合わせるために小さく早く出す。

## ⑦ 残す（知識永続化・想起）
✅既存（`memory/`・obsidian-vault・CLAUDE.md＝「AIへの個人コンテキスト」そのもの）。
- 追加: **Evergreen Notes**（Andy Matuschak）— コンセプト紐付け・更新され続ける粒度。PARAと組合せ。
- **PARA**（Forte）— Projects/Areas/Resources/Archives。導入コスト低。
- **不採用（2026-06-18）**: claude-obsidian / obsidian-Smart2Brain 等の自動second-brainツール。理由＝既存の手動キュレーション（memory/・knowledge/・CLAUDE.md）と重複し、"大量自動キャプチャ"は signal-first 方針と逆＝ノイズ源。知識ベースの価値は「何を入れるかの人間の判断」にあり、そこは自動化しない。原則(Evergreen/PARA)のみ採用。

## ⑧ 改善（学習ループを回す）
- **AAR 4問**（意図/実際/差分/次）— タスク後3分。`result.md`・`SESSION_NOTES`習慣に直結。最小で閉じる。
- **Blameless Postmortem**（Google SRE Book Ch.15・無料）— 「なぜプロセスが許したか」。`failure_patterns/`の書式。
- **週次レビュー**（GTD）— 金曜30分で棚卸し。GTDの他は使わなくてもこれだけで回収。
- **インシデント即日記録** — 鮮度のある記録が根本原因分析の精度を変える。

## 横断A：経済性（build / buy / delegate）
✅部分（model routing・委譲規律）。判断の型化余地: 自作 vs 既製 vs 外注AI を毎回再発明しない。Two-way door と併用。

## 横断B：倫理・法務（IP / NDA / データ境界 / ライセンス）★コンサルで必須・未整備
クライアントデータ境界・NDA・著作権・OSSライセンスの判断チェックリスト。実案件で事故ると信用を一発で失う層。ライセンス確認は既に実践（MIT/Apache確認の習慣あり）。

## 継続トラック：能力開発（番号外・タスク横断）
番号付き段階ではなく、各タスクで毎回通すものでもない。①「集める」と⑧「改善」から分け、必要に応じて継続する能力開発。
- **Feynman技法** — 白紙に平易な言葉で説明→詰まった所が理解の穴。ツール不要。
- **Interleaving（交互練習）** — Rohrer & Taylor 2007。複数スキルを混ぜると長期定着↑（直感と逆）。
- **Deliberate Practice** — Ericsson "Peak" 2016。不快ゾーン＋即フィードバック＋弱点集中。量より質。
- **最小実装→原理抽出** — README→最小実装(LLM生成可)→ソース逆読み。新OSS把握の型。
- ツール: **Anki + SM-2**（間隔反復・学んだ当日カード化）。

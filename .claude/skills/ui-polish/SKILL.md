# UI Polish

## Mission
画面・ダッシュボード・デモの「詰めの甘さ」を消す。機能が同じでも、仕上げで信頼感（特にクライアント前）が変わる。**機能が完成してから**通す最後のゲート。

> 具体チェックは wpgaurav/claude-code-skills (MIT) の polish から、Streamlit/DS デモに効く項目だけ吸収。純Webフロント項目（CLS/FOUT/retina/60fps/ARIA詳細）は [[frontend-build]] 側の本格Web時にのみ適用。

## 前提（着手前に確認）
- 機能的に完成しているか（未完成を磨かない）。
- 品質バー（PoC/デモ vs 本番）と、出すまでの時間。30分で出すなら磨きすぎない（triage）。

## Polish 次元（体系的に）
### 余白・整列
- **余白の一貫性**: 4 / 8 / 16px のような一定スケール。ランダムな 13px を消す。
- **整列**: 左端・ベースラインを揃える。グリッドに乗せる。中央寄せと左寄せを混ぜない。
- **光学的整列**: アイコンは視覚的重心でわずかにオフセットして"揃って見える"ように。

### 視覚階層
- 1画面に主役を1つ。サイズ・太さ・コントラストで「見る順番」を作る。全部強調＝何も強調していない。

### タイポgrafi
- 階層の一貫性（同じ要素は同じサイズ/太さ）。
- 1行の文字数: 欧文45-75字 / 和文 約40字を上限目安に折る。
- 行頭・行末の孤立（widow/orphan）を避ける。日本語フォントを明示。

### 色・コントラスト
- アクセント色は1〜2色。意味のない多色を使わない。
- テキストと背景のコントラストを確保（薄いグレーの上の薄字を避ける）。
- 純グレー/純黒を避けわずかに色味を持たせると締まる。色背景の上にグレー文字を置かない。
- チャートの配色・y軸ルールは [[viz-style]]（jet/rainbow禁止・棒は0起点）に従う。

### インタラクション状態（**漏らさない**）
インタラクティブ要素には全状態を: **default / hover / focus / 選択中 / 無効 / loading / error / 空(empty)**。
状態の欠落が混乱と「壊れた体験」を生む。

### コンテンツ・コピー
- 用語の一貫性（同じものを同じ名前で）。大文字小文字/句点の統一（ラベルに句点を付けるなら全ラベルに）。
- 文言は [[stop-slop]] に通す。

## Workflow
1. 機能が動いた後にこのゲートを通す。
2. 余白スケール統一 → 整列 → 主役を1つに → 配色1〜2色 → 全状態を埋める → コピー統一。
3. 本番耐性は [[ship-harden]]、設計の崩れは [[ui-ux-design]] に戻す。

## Guardrails
- **見た目に時間をかけすぎない**。PoC/デモは「清潔で読める」で十分。
- 情報設計（[[ui-ux-design]]）を崩してまで装飾しない。
- 実装は委譲してよい（[[frontend-build]]）。このスキルは"判断と指摘"の層。
- 一部だけ完璧で他がラフ、を作らない。品質レベルを画面全体で揃える。

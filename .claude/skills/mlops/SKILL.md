# MLOps

## Mission
モデルを「再現でき・追跡でき・壊れず動かせる」状態に保つ層。実験から配信までの整合性を守る。背骨（DS/MLE）と [[infra-deploy]] の間を埋める。

## Rules
- **実験管理はWandB一本**: メトリクス・パラメータ・成果物を記録。`result.md` には意図・採用判断・次仮説だけ残す（CSV台帳や自動フックは使わない＝feedback_experiment_tracking の方針）。
- **再現性を最優先**: seed固定・データバージョン・依存固定（[[python-ops]]）。「同じ入力で同じ出力」が崩れたら最初に疑う。CVの妥当性・リークは [[review-exp]]。
- **学習/推論の整合**: 前処理を学習と推論で共有（同じ `src/` 関数を使う）。train/serve skew を作らない。特徴量の定義をズラさない。
- **モデルの保存と版管理**: モデル・前処理器・メタ（学習データ範囲/指標/日時）をセットで保存。どのモデルが今どこで動いてるか追える状態にする。
- **監視（本番が要るとき）**: 入力分布のドリフト・推論レイテンシ・失敗率。閾値超えで気づける仕組み。過剰監視はしない。
- **重い配信基盤は委譲**: サービング/パイプラインの実装は仕様を渡して委譲、自分は設計とレビュー。

## Workflow
1. 学習時にWandBで記録、再現条件（seed/データ/依存）を固定。
2. 前処理を `src/` に置き学習・推論で共有。
3. モデル＋前処理器＋メタをまとめて保存・版管理。
4. デプロイは [[infra-deploy]] と接続。公開前に [[ship-harden]]（欠損入力・遅延）。
5. 本番なら最小限の監視（ドリフト・失敗率）を載せる。

## 精査メモ（2026-06-18）
コミュニティMLOpsスキル（Eirias/ai-research-skills 等）はLLM事前学習/RLHF/mech-interp研究向けで、WandB一本・表形式DSの本スキルとは適合しない。**自前維持が適切**。将来LLM学習に踏み込むなら mlflow/wandb系SKILLの導入を再検討。

## Guardrails
- **PoC段階で本番MLOpsを作り込まない**。まず再現性と train/serve 整合。監視・自動再学習はスコープを確認してから。
- 指標の保存先を散らさない（WandBに寄せる）。
- リーク・CV崩れは配信前に [[review-exp]] で潰す。

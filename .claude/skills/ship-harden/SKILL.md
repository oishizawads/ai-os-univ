# Ship Harden

## Mission
「自分の手元では動く」を「人に触らせても壊れない」に上げる。デモ/納品物が想定外入力で落ちる事故を防ぐ。**理想的なデータでしか動かないものは本番ではない。**

> エッジケースの網羅マトリクスは wpgaurav/claude-code-skills (MIT) の harden から、DS/Streamlit/データ処理に効く概念を吸収。i18n/RTL/CSS など純Web実装は [[frontend-build]] 側で扱う。

## 極端入力でテスト（まず壊しにいく）
- **テキスト**: 非常に長い / 空 / 1文字 / 絵文字・特殊文字・多言語
- **数値**: 巨大数（百万・億）/ 負 / 0 / 桁あふれ / NaN・Inf
- **件数**: 0件（空）/ 1件 / 1000件以上（描画崩れ・処理時間）
- **データ(DS特有)**: 欠損(NaN)・空DataFrame・全列同値・型不一致・想定外カテゴリ

## エラーシナリオ
- ネットワーク: オフライン / 遅延 / タイムアウト
- API: 400(検証) / 401(再ログイン) / 403(権限) / 404(無し) / 429(レート) / 500(汎用＋連絡先)
- **例外を握りつぶさない**（[[silent-failure-hunter]] 観点）。失敗時にユーザーへ何が起きたか伝え、回復手段（再試行）を示す。
- 入力は保持（エラーでユーザー入力を消さない）。

## 状態（空でないことを保証）
- **空状態**: 「データなし」を blank で放置せず、次のアクションを示す。
- **ローディング**: 非同期処理に「読み込み中…」、長い処理は何をしているか表示。
- **二重送信防止**: 実行ボタンを処理中は無効化。連打・競合（race）を防ぐ。

## 大量データ
- 全件を一度に読まない（ページング/サンプリング/遅延）。フィルタ・検索を用意。処理時間を見積もる。

## 再現性・秘密情報（DS/納品で必須）
- 環境依存（パス・OS・依存バージョン）で動かなくならないか。パスは [[path-io]]、データ層は [[safe-data-handling]]、環境固定は [[python-ops]]。
- **APIキー・PII・内部パスを画面/ログ/コミットに出さない**（[[safe-data-handling]]）。一度公開すればキャッシュ/インデックスされうる。
- クライアントデータを出す前に「出していいデータか」を確認。ダミー/仮データで足りるなら使う（MTJの仮データ明示の流儀）。

## Workflow
1. 機能と仕上げ（[[ui-polish]]）の後、出す直前に通す。
2. 極端入力 → エラー時挙動 → 空/ローディング/二重送信 → 大量データ → 再現性 → 秘密情報、の順で1つずつ壊す。
3. クライアント前デモは「触られて困る操作」を事前に試し、ガードか非表示に。

## Guardrails
- **過剰な堅牢化をしない**。PoCは「想定操作で壊れない＋秘密情報を漏らさない＋空/エラーで落ちない」で十分。本番SLA級・監視・自動再学習はスコープ確認後（[[infra-deploy]] / [[mlops]]）。
- i18n(RTL/多言語レイアウト)・CSS overflow など純Web実装は委譲（[[frontend-build]]）。このスキルは"何を潰すか"の判断層。
- 1コンポーネントのエラーでインターフェース全体を止めない。

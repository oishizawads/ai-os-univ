# Safe Data Handling

## Mission
入力データを壊さず、機密を漏らさず、生成物の置き場を一貫させる。データを触る全タスクで適用する。

## Rules
- `data/raw/` と `data/external/` は**読み取り専用**。上書き・削除・整形保存をしない。
- 生成・中間物は `data/interim/`、最終加工物は `data/processed/` に書く。
- ディレクトリ構成が違うプロジェクトでも「元データ層は不変・派生物は別層」の原則を守る。
- APIキー・トークン・個人識別情報（PII：氏名/住所/電話/メール/顧客ID等）を**コードにもコミットにも含めない**。
- サンプルやログに実データを貼るときは、機密列をマスク/ダミー化してから。

## Workflow
1. 触る前に、入力がどの層か確認（raw/external なら変更しない前提で読む）。
2. 出力先を `interim` か `processed` に決め、パスを明示する（[[path-io]] に従う）。
3. 出力前に「秘密情報・PIIが混ざっていないか」を必ず確認。
4. 大きな生成物は再現方法（スクリプト/seed）を残し、データ自体のコミットは避ける。

## Guardrails
- raw を「ちょっと整形して保存し直す」をしない。派生は必ず別ファイル/別層へ。
- 「とりあえずCSVをコミット」をしない。機密混入の温床。
- 由来不明データを成果物として扱わない。出所を記録する。
- 迷ったら不変側に倒す（消さない・上書きしない）。

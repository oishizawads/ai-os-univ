# SQL Analysis

## Mission
正しくて読める分析SQLを書き、暗黙の行数膨張や事故を防ぐ。SQL を書く全タスクで適用する。

## Rules
- `SELECT *` を避け、必要な列を明示する。
- 複雑なクエリは CTE（`WITH`）で段階を分け、各段の意味が読めるようにする。
- join の前後で**行数を検証**する（意図しない増殖＝多対多や重複キーを早期に検知）。
- 集計の粒度（GROUP BY のキー）と重複排除の方針を明示する。
- `DROP` / `DELETE` / `UPDATE` / `TRUNCATE` などの破壊・変更操作は、**明示的に依頼されたときだけ**行う。勝手に実行しない。

## Workflow
1. 出したい粒度（1行＝何の単位か）を先に決める。
2. CTE で「元データ → フィルタ → 集計 → 結合」を分けて書く。
3. join したら直後に件数を確認（増殖していないか）。
4. 列は明示。型・NULL の扱いを意識する。

## Guardrails
- `SELECT *` を本番/共有クエリに残さない。
- join 結果の行数を確認せずに集計へ進まない。
- 破壊操作を「ついでに」実行しない。依頼の明示を確認する。
- データ層の不変性は [[safe-data-handling]] に従う。

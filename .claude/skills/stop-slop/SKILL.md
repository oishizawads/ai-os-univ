# Stop Slop

## Mission
専門外の領域ほど出る「AI臭い・薄い文章」を全成果物で拾う。読み手の時間を奪う定型を削り、主張を立たせる。日本語クライアント文書が主対象だが、英語(README/コミット/海外向け)にも適用。

> 構造アンチパターンとフレーズ集の元ネタは wpgaurav/claude-code-skills (MIT) を日英・クライアント文脈向けに再構成。詳細リストは `references/` にオンデマンド分離（常駐ゼロ）。

## Core Rules
1. **前置きを切る**。「〜について考えてみましょう」「結論から言うと（と言いつつ長い）」等の枕を消し、内容から始める。→ `references/phrases.md`
2. **定型構造を崩す**。二項対立の煽り（「Xではない。Yだ」）/ 体言止め連打のドラマ化 / 修辞的問いかけ。→ `references/structures.md`
3. **リズムを変える**。文長を混ぜる。3項目より2項目。段落の結びを毎回同じ形にしない。
4. **読み手を信頼する**。事実を直接述べる。過剰な軟化・言い訳・手取り足取りを削る。
5. **引用句っぽい一文を消す**。決め台詞・キャッチー風の一文は書き換える。
6. **数字と固有名詞**を入れる。「大幅に改善」→「処理時間を40%短縮」。
7. **実証の偽装をしない**。やっていないことを実証済みに見せない／効果を断定しない（クライアント文書では特に → feedback_client_deliverable_hygiene と [[work-implementation]]）。

## Quick Checks（納品前）
- 3文連続で同じ長さ → 1つ崩す
- 段落が毎回キメ台詞で終わる → 変える
- 暴露の前の em-dash（—）→ 消す
- 比喩を説明している → 比喩を信じて説明を消す
- 同じ概念を3つの別名で呼んでいる（ツール→基盤→ソリューション）→ 1つに固定して繰り返す
- 「〜という役割を果たす」で「〜である」が通る → 短い方
- 「XからYまで」range の積み重ね → 一番効く具体例1つ
- 結びの段落がどの記事にも使える一般論 → その案件固有の話に

## Self-Audit（最終パス）
書いた後に問う: **「これが一発でAI生成だと分かる点は？」** 各段落で:
1. 類義語サイクリング（同じものを毎回違う語で）
2. -ing/連体修飾の連発（〜することで、〜を通じて、〜しながら）
3. 重要性インフレ（極めて重要・画期的・革新的・次のレベル）
4. 偽の網羅（〜から〜まで、〜であれ〜であれ）
5. 一般的ポジティブな締め（今後が楽しみ・時間が解決する）

見つけた全インスタンスを直し、もう一度読む。

## Scoring（1-10で5軸・合計35未満は revise）
| 軸 | 問い |
|---|---|
| 直接性 | 主張しているか、告知しているだけか |
| リズム | 変化があるか、機械的か |
| 信頼 | 読み手の知性を尊重しているか |
| 自然さ | 人間が書いたように読めるか |
| 密度 | 削れる箇所はないか |

## Workflow
1. 下書きを書く（速度優先でよい）。
2. Core Rules → Quick Checks → Self-Audit → Scoring の順で通す。
3. 仕上げの視覚面は [[ui-polish]]、本番耐性は [[ship-harden]] へ。

## Guardrails
- 短くするために**事実・前提・限界の明示を削らない**（特にクライアント文書）。締める≠情報を落とす。
- 対象は**外向き成果物**（提案書・スライド・レポート・README・クライアント宛て）。ラフな社内チャットに過剰適用しない。
- トーンは相手に合わせる。固い文を一律に崩さない。日本語の禁止語は機械的に消さず、文意が通るか確認してから。

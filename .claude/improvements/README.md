# workspace 改善ディレクトリ

> workspace の運用は生きている限り続けていく。
> このディレクトリは、改善アイデアの発掘・実験・採用・見送りを記録する場所。

---

## ファイル構成

| ファイル/ディレクトリ | 用途 |
|---|---|
| `README.md` | このディレクトリの説明と運用ルール（このファイル） |
| `ideas.md` | 思いついた改善アイデアを貯める。未整理でも OK |
| `experiments.md` | 試した改善の記録。期間・効果・所感を残す |
| `adopted.md` | 正式に採用した改善。いつから運用しているか記録 |
| `rejected.md` | 見送った改善。なぜ採用しなかったか記録 |
| `prompts/` | AI 同士のレビュー・対話用プロンプト |
| `debate/` | AI 同士の対話ログを保存（自動生成） |

---

## 運用ルール

1. **アイデアは ideas.md に先に書く**
   - 完璧に整理しなくてよい。キーワードと直感的な価値だけ書いておく。

2. **月次レビューで整理する**
   - 毎月最終日曜日に ideas.md を見直す。
   - 試すものは experiments.md に移す。
   - 採用したものは adopted.md に移す。
   - 見送ったものは rejected.md に移す。

3. **無理に全部導入しない**
   - 管理コストが効果を上回る場合は見送る。
   - 最小構成から始めて、定着してから次を追加する。

4. **改善の効果を主観ではなく観察で測る**
   - 「気持ちよくなった」ではなく、「週次レビュー時間が 20分減った」など具体的に。
   - experiments.md に数値や事実を残す。

5. **失敗も資産にする**
   - 採用してうまくいかなかったものは rejected.md に「なぜうまくいかなかったか」を書く。
   - 将来同じ轍を踏まないための材料。

## 追加候補のファイル

必要に応じて追加してよい：

- `metrics.md` — 改善の効果測定指標
- `templates/` — 実験記録や採用記録のテンプレート
- `backlog/` — 将来検討したい大きなテーマ

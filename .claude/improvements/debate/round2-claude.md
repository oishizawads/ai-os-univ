## 2. 守る／強化する点（陣地でなく設計で返す）

### A. 閉ループ化 — Codex 最強の批判 #5 を設計で解決

Codex は正しい：制御規則がなければ #5/#4/#2 は**並列ログ**にすぎない。だから明示的な制御規則を足す（これが私の Round 2 の中心的な追加）。

```
制御規則（週次レビューに常設）:
  IF 直近2日のコンディション平均 < 3
  THEN 今週は必ず次のいずれかを実行:
       (a) current-focus の1タスクを延期に移す, または
       (b) not-doing リストに1件追加する
```

これでコンディション記録が初めて**タスク受任・延期を実際に変更する**。Codex 自身の #4 継続条件「1回以上計画変更に使えたら継続」は、実は一回限りのゲートに化けた制御規則。私はそれを**常設ルール**に格上げする。並列ログ→閉ループへの差分はこの一文だけ。

### B. #2 を「1-5 順序尺度」から確率予測へ格上げ

Codex は正しい：1-5 は順序尺度で較正にならない。ならば**較正が成立する形に上げる**のが擁護の仕事。

- 確信度は **% で記録**（例：70%）。解決日と**二値の成否条件を事前固定**。
- 解決した予測が **N≈10〜20 件**たまった時点で、予測% と実現頻度を突き合わせ**較正曲線／Brier 的指標**を出す。
- これで「テールリスク保険」の反証不能主張も解消する：保険ではなく、**事後に較正可能な予測ログ**として価値を測る。較正がズレていればそれ自体が学び。

`DECISION_LOG.md` の純増は **確率・解決日・成否条件・結果の4フィールドのみ**（基盤は既存、Codex 指摘どおり）。新システムは作らない。

### C. 「寄生＝コスト消滅ではない」への限定的反論

認める、消滅ではない。ただし**固定コスト vs 限界コスト**の区別は残る。新しい独立儀式は「設定＋想起＋文脈切替」の固定費がかかる。既に毎週回す週次レビューに1欄足すのは、その欄の記入時間という限界費だけ。だから「ゼロ」は撤回するが「相対的に安い」は維持する。欄を無制限に足せば週次が重くなる点は同意——だから足すのは**制御規則1本＋#5/#4 の最小欄**に限定する。

### D. Workspace健康診断の一点だけ留保

monthly-review は「成果・指標・戦略」のレビューであって、「滞留ファイル・古い記録・未整理領域のファイルシステム走査」は含まない。とはいえこれは**新コマンド不要**で、monthly-review のチェックリストに1行足せば済む（#65 の実装案=新コマンドは撤回）。優先度は最後尾。

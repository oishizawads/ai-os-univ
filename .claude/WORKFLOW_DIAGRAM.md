

# Workspace ワークフロー図

> 現行運用フローのビジュアル要約。出典は `CLAUDE.md`（トリアージ）／`.claude/META_MAP.md`（どう回すか・8層）／`.claude/CAPABILITY_MAP.md`（何をやるか・22領域）。
> 最終更新: 2026-06-20

## 一言で
全タスクをまず1拍トリアージ → 8層パイプラインのどこかに位置づけ → 軽いものは即応・重いものだけ深掘り → 実装も分析も Claude が直接やるのが既定（委譲は任意の逃げ道）→ 品質層を通して記録。

## 図2: META_MAP の8層パイプライン（「どう回すか」）

```
 集める → 考える → 決める → 動かす → 検証 → 伝える → 残す → 改善
   ①       ②       ③★      ④       ⑤★     ⑥       ⑦      ⑧
   │        │       │        │        │       │        │       │
 入力収集  思考FW   トリアージ AI運用  AI出力  統合説得 知識永続 学習ループ
 データ   MECE     Two-way   Claude  LLM-    SCQ/    memory/  AAR4問
 既存notes  ピラミッド door    直接    Judge   Assert  PARA     週次
 制約/PII Cynefin  Hell yes  /委譲   2経路   -Evid   Evergreen Postmortem
                   Pre-mortem        突合せ

        ＋ 横断A: 経済性 (build / buy / delegate)
        ＋ 横断B: 倫理・法務 (IP / NDA / データ境界 / ライセンス)★
        ＋ 継続トラック: 能力開発 (Feynman / Interleaving / Deliberate Practice / Anki) ※番号外

  ★ = 最重要の穴（③決める・⑤検証を優先）。能力開発は継続トラックで優先内面化。
```

トリアージは毎回この8層の **どこに居るか** を当てる作業。重い案件だけ該当層を深掘りする。

## 図3: 誰が動くか × 知識のロード方針（CAPABILITY_MAP）

```
  ┌───────────────────────── 実行主体 ─────────────────────────┐
  │  既定 = Claude 直接（設計も実装も分析も最終判断も）         │
  │                                                            │
  │  委譲（任意・実利があるときだけ）:                          │
  │    /opencode-coder … 高効率・量産実装                       │
  │    /gemini-coder   … Web リサーチ・実装セカンドオピニオン   │
  │    /codex-coder    … ⚠️節約・実案件レビュー/重要実装        │
  │    decision-lab    … 不確実性の高い分析（多経路・収束判定） │
  └────────────────────────────────────────────────────────────┘

  知識のロード（3層 = 背骨は深く、周辺は1領域1正典で軽く）:

   ┌──────────────┐  常駐・深く
   │ 背骨 DS/MLE   │  experiment-workflow / eda / viz-style / sql-analysis
   └──────────────┘
   ┌──────────────┐  オンデマンド（その文脈でだけ・1領域1本）
   │ 領域正典 ×22  │  frontend-build / infra-deploy / mlops / ui-ux-design / causal-inference …
   └──────────────┘
   ┌──────────────┐  常駐・少数（全成果物に通す標準ゲート）
   │ 品質層        │  stop-slop / ui-polish / ship-harden
   └──────────────┘
```

**3つの規律**: ①1領域1正典（役割を被らせない）②品質層は常駐 ③重実装も Claude 直接が既定。

## 補足（運用の固定ルール）
- 可逆な決定は速く、不可逆だけ慎重（Two-way door）。「たぶんYes は全部No」(Hell yes, or no)。
- 単一経路を信用しない → AI 生成の数値・引用・コードは 2経路 or 原典で検証（⑤が最重要の穴）。
- rtk / `/route` / `/orchestrate` / ai-delegate は廃止・dormant（2026-06-19）。委譲は直接コマンドのみ。
- ハンドオフ前提の案件は記録（`SESSION_NOTES` / `decisions/` / `failure_patterns/`）を最優先。
- 詳細は `.claude/REFERENCE.md`、ルーティング決定木は `ai-os/knowledge/frameworks/model_routing.md`。

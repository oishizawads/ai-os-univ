# RTK (Rust Token Killer) 活用ガイドライン

> **Status (2026-06-21): RTK は任意・非必須。** 既定ワークフローには含めない（実測削減 ~0.7%、auto-rewrite フックなし、`rtk` は PATH 未登録）。以下は手動で使う場合の参考。正典は root `CLAUDE.md`。

## 概要
AI-OS ワークフローにおいて、トークン消費削減のために `rtk` を**任意で**利用できる（全エージェント必須ではない）。

## 各エージェントの役割と RTK の設定

### 1. Claude Code (CC) - 計画フェーズ
*   **役割**: アーキテクチャ設計、タスクの分解、実装計画の策定。
*   **RTK の活用**:
    *   `git status` や `ls` の出力を圧縮し、広範なファイル構造を少ないトークンで把握します。
    *   （手動実行のみ。自動適用フックは入れない＝罠回避のため。）

### 2. Codex / Gemini - 実装・検証フェーズ
*   **役割**: コードの生成、テストの実行、デバッグ。
*   **RTK の活用**:
    *   **テスト実行**: `npm test`, `cargo test`, `pytest` などの冗長なパスログを圧縮し、失敗した箇所の特定に集中させます。
    *   **Git 操作**: 変更箇所の確認（`git diff`）において、本質的な変更のみを抽出します。

## 推奨コマンド用法

| 目的 | コマンド | RTK の効果 |
| :--- | :--- | :--- |
| プロジェクト状態確認 | `git status` | ファイルリストを最小限に要約 |
| テスト実行 | `rtk <test-cmd>` | 成功ログを隠蔽し、エラーのみを強調 |
| ファイル探索 | `rtk find . -name "*.py"` | パスのみを簡潔にリストアップ |
| 統計確認 | `rtk gain` | 現在のセッションでの節約量を確認 |

## 注意事項
*   **Tee 機能**: `rtk` は出力を圧縮しますが、元のフルログは一時ファイルに保存されています。詳細なログが必要な場合はエージェントに `cat` 等でログを直接読ませるよう指示してください。
*   **バイナリ位置**: `C:\workspace\bin\rtk.exe` を使用してください。

# 仮説思考 — 問題発見・解決の発想法

> 出典: 内田和成『仮説思考 BCG流』
> 用途: 情報が少ない段階から答えに向かって進むあらゆる思考・分析の基盤

---

## 0. 根本原則

```
仮説なき情報収集は、無限に続く砂漠の旅と同じ。
仮説があれば、最短距離で答えに辿り着ける。
```

- **仮説思考** = 今持っている情報を元に「最善の答え（仮説）」を出し、それを検証・更新する思考法
- 完璧な情報を揃えてから考えるのではなく、**不完全な情報でも答えを出す力**

---

## 1. 仮説の2種類

### 課題設定仮説（What's the issue?）
「何が本当の問題か」についての仮説。表面的な現象ではなく本質的な原因を特定する。

### 解決策仮説（What's the solution?）
「どう解決するか」についての仮説。課題設定仮説が固まってから立てる（順番が重要）。

---

## 2. 空・雨・傘

仮説思考の最も基本的なフレームワーク。

| レベル | 問い | 例 |
|-------|------|---|
| **空** | 何が起きているか（事実） | 「Q1の営業成績が全員20%下落」 |
| **雨** | なぜ起きているか（仮説） | 「新製品への切り替え期で説明が追いついていない」 |
| **傘** | だからどうするか（行動） | 「新製品のトークスクリプトと同行訪問を今月中に実施」 |

### よくある失敗
- **空だけ語る**: 「売上が落ちています」（で？という状態）
- **雨を飛ばす**: 空→傘に直行（なぜその行動か説明できない）

---

## 3. 仮説を検証する

1. **キークエスチョンを特定**: 「この仮説が正しいなら、必ず観察されるはずのことは何か？」
2. **反証から入る**: 仮説を支持する情報より、否定する情報を先に探す
3. **最小の情報で最大の検証**: 「これを見れば答えが出る」という1点を見つける
4. **仮説を更新**: 崩れたら修正する。崩れること自体は失敗ではない

---

## 4. チェックリスト

### 何かを始める前に

```
[ ] 今の段階で「答えの仮説」を一言で言えるか？
[ ] 課題設定仮説（何が問題か）と解決策仮説（どう解くか）を区別しているか？
[ ] 空（事実）・雨（解釈）・傘（行動）を分けて書けるか？
```

### 情報収集・分析中に

```
[ ] この分析は仮説のどこを検証しているか？
[ ] 仮説を否定するデータを積極的に探したか？
[ ] 「全データを集めてから考える」モードに入っていないか？
```

---

## Claude に適用する場合のプロンプト冒頭

```
仮説思考で考えてください。
1. 今の段階で「答えの仮説」を一言で出す
2. その仮説を「空・雨・傘」に分解する
3. 仮説を否定する情報を先に探す（反証重視）
4. 最小の情報で最大の検証を行う設計をする
5. 検証結果に基づき、仮説を更新する
---
[本題をここに記述]
```

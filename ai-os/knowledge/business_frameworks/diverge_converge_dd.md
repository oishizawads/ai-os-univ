# ダブル・ダイヤモンド — デザイン思考フレームワーク

> 出典: 英国デザイン協議会 (Design Council)
> 用途: 問題の再定義、多角的なアイデア創出、解決策の収束

---

## 0. 根本原則

```
正しい問いを見つける(Do the right thing) × 正しく解く(Do the thing right)
```

- **発散(Diverge)**: 可能性を広げ、選択肢を増やす。
- **収束(Converge)**: 焦点を絞り、意思決定を行う。
- この「発散と収束」を2回繰り返すことで、表面的な解決策ではなく、本質的な課題解決を目指す。

---

## 1. 4つのフェーズ

### 1. 発見 (Discover) - [発散]
市場、顧客、環境を深く理解するためのフェーズ。
- ユーザーインタビュー、観察、データ収集。
- **目的**: 予断を持たずに情報を広げ、現状を把握する。

### 2. 定義 (Define) - [収束]
収集した情報から、解決すべき「真の課題」を特定するフェーズ。
- 共通パターンの特定、ユーザー像（ペルソナ）の確立、ジャーニーマップ。
- **目的**: 実行可能で意味のある「問い」に凝縮する。

### 3. 展開 (Develop) - [発散]
特定された課題に対する、多様な解決策を考案するフェーズ。
- ブレインストーミング、プロトタイピング、マルチシナリオ検討。
- **目的**: 既存の枠組みにとらわれず、多くの選択肢を出す。

### 4. 届ける (Deliver) - [収束]
解決策を絞り込み、テストし、完成させるフェーズ。
- ユーザーテスト、フィードバック収集、実装準備。
- **目的**: 価値を最大化し、実現可能な形に磨き上げる。

---

## 2. デザイン思考の5つのマインドセット

1. **ユーザー中心**: 常にユーザーの視点から出発する。
2. **共感**: 数値だけでなく、感情や文脈を理解する。
3. **視覚化**: 言葉だけでなく、絵やプロトタイプで共有する。
4. **反復 (Iteration)**: 一回で正解を出そうとせず、何度も回す。
5. **コラボレーション**: 多様なバックグラウンドを持つ人を巻き込む。

---

## 3. 実践のコツ

- **「定義」を飛ばさない**: いきなり「展開（アイデア出し）」に行かない。問いが間違っていれば、最高のアイデアも無意味になる。
- **発散と収束を分ける**: アイデアを出している最中に批判（収束）しない。
- **失敗を早く、安く**: 完璧なものを作る前に、紙のプロトタイプなどで素早くテストする。

---

## 4. チェックリスト

### プロジェクトの初期段階

```
[ ] いきなり解決策から考えていないか？
[ ] 「発見」フェーズで、自分たちの想定外の事実は見つかったか？
[ ] 「定義」された問いは、具体的で行動可能なものか？
[ ] アイデア出し（展開）で、最低でも3つ以上の異なるアプローチを出したか？
[ ] ユーザーからのフィードバックを反映する仕組みはあるか？
```

## Claude に適用する場合のプロンプト冒頭

```
ダブル・ダイヤモンドのフレームワークで考えてください。
1. [発見]: 私の要望の背景にある潜在的なニーズや、見落としている可能性のある観点を広げて提示する
2. [定義]: 広げた情報から、今解くべき「真の課題」を1つに絞り込む
3. [展開]: その課題に対し、アプローチの異なる解決策を3つ提案する
4. [届ける]: 最も有望な解決策を選び、具体的な実行ステップと検証方法をまとめる
---
[本題をここに記述]
```

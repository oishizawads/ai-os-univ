# システム思考 — 構造理解フレームワーク

> 出典: ドネラ・H・メドウズ『世界はシステムで動く』
> 用途: 複雑な問題・反直観的な現象・長期的変化を理解する

---

## 0. 根本原則

```
問題の原因は「システムの外」ではなく「システムの構造」の中にある。
要素を変えるより、構造を変えよ。
```

- 短期的な介入が長期的な悪化を招く（例: バグを直すたびに別のバグが生まれる）
- 善意の介入が逆効果になる（「症状」を抑えると「根本原因」が悪化する）

---

## 1. システムの3要素

### ストック（Stock）
システム内に**蓄積・貯留**されるもの。ある時点の「量」。
- 例: 水槽の水量、人口、信頼感、知識、技術的負債

### フロー（Flow）
ストックを**変化させる速度**。単位時間あたりの量。
- 例: 降水量・蒸発量、出生率・死亡率、学習速度

### フィードバックループ
ストックの変化が、次のフローに影響する**循環**。

---

## 2. フィードバックループの2種類

### 強化ループ（Rループ）
変化が同じ方向に増幅される。指数的成長または崩壊をもたらす。
- 口コミ、学習の加速、貧困の連鎖、技術的負債の蓄積

### バランシングループ（Bループ）
目標値に向かって調整される。安定・定常状態を生み出す。
- サーモスタット、在庫管理、体温調節
- **遅延があると振動や過剰補正が起きる**

---

## 3. システムの8つの罠（代表例）

| 罠 | 構造 | 例 |
|---|------|---|
| **政策抵抗** | 複数アクターが互いに補正 | 規制強化→地下化 |
| **公有地の悲劇** | 個人の利益・全体のコスト | 技術的負債の蓄積 |
| **目標のドリフト** | 目標自体を下げる | 品質基準を緩める |
| **依存と侵食** | 症状対処が根本原因を侵食 | 応急処置が定常化 |
| **目的の誤り** | 代理指標を最適化 | KPI達成だが価値なし |

---

## 4. チェックリスト

### システムを見るとき

```
[ ] 「問題の原因」を人・部門・イベントに帰属していないか？
[ ] 強化ループとバランシングループを識別できているか？
[ ] 遅延はどこにあるか？どれくらいの長さか？
[ ] 「症状への対処」をしているか？「根本原因への対処」をしているか？
[ ] 「8つの罠」のどれかに当てはまっていないか？
```

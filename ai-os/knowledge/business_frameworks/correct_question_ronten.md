# 論点思考 — 問題設定フレームワーク

> 出典: 内田和成『論点思考 BCG流 問題設定の技術』
> 用途: 分析・議論の最初のステップ。「何を考えるか」を正しく設定する

---

## 0. 根本原則

```
間違った問題を正しく解いても、価値はゼロどころかマイナスになる。
論点思考とは「解くべき問題を正しく設定する」技術である。
```

- **論点** = 「今、この状況で考えるべき問い」。答えると「状況が動く」問い。
- **論点思考 vs 仮説思考**: 論点思考は「何を問うか」を決め、仮説思考は「その問いにどう答えるか」を決める。

---

## 1. 論点の4段階構造

```
全体論点（Overall Issue）
    ↓ 分解
サブ論点1  サブ論点2  サブ論点3
    ↓ さらに分解
サブサブ論点 …
```

### 全体論点の条件
1. 1文で書ける
2. Yesか Noか、AかBかで答えられる
3. 答えると「何かが変わる・動く」
4. 今の状況で実際に検討に値する

---

## 2. 論点を見つける3ステップ

### Step 1: 論点候補を広げる
「この状況で答えが必要な問いは何か？」を全て列挙する。

### Step 2: 論点を絞り込む（4つの基準）

| 基準 | 問い |
|------|------|
| **重要性** | これを解くと、どれほど大きな変化が起きるか？ |
| **緊急性** | 今、この状況で答えるべき問いか？ |
| **解決可能性** | 今の時間・情報・リソースで答えが出せるか？ |
| **依存関係** | この論点の答えが出ないと、他の論点に取り組めないか？ |

### Step 3: 論点の構造化（ツリー化）
絞り込んだ全体論点を、MECEなサブ論点に分解する。

---

## 3. 論点の「ずれ」を避ける

### よくある3パターン

- **広すぎる論点**: 「業績を改善するには」→ 答えようがない
- **狭すぎる論点**: 「チラシの最適なデザインは」→ 本当の論点は「集客低下の原因」
- **依頼主の思い込みに乗る**: 「コストを削減するためにどの部門を縮小すべきか」→ 前提が「コスト削減が唯一の解」

### 対策
- 依頼された問いの「前提」を疑う
- より上位の論点（Why?）を考える
- この問いに答えても状況が変わらない可能性はないか？

---

## 4. チェックリスト

### 作業・分析を始める前に

```
[ ] 今の「論点（問い）」を1文で書けるか？
[ ] その論点は「依頼された問い」と同じか？（ずれていないか）
[ ] 論点の前提を疑ったか？（より上位の問いはないか）
[ ] 論点に答えると何が変わるか（重要性）を確認したか？
[ ] 今の時間・リソースで答えが出せる論点か（解決可能性）？
[ ] サブ論点はMECEになっているか？
```

---

## Claude に適用する場合のプロンプト冒頭

```
論点思考で考えてください。
1. 依頼された問いの「前提」を疑い、より上位の論点を探す
2. 今の状況で「考えるべき問い（論点）」を1文で設定する
3. その論点をMECEなサブ論点に分解する
4. 各サブ論点の重要性・緊急性・解決可能性で優先順位をつける
---
[本題をここに記述]
```

# クネビン・フレームワーク (Cynefin) — 意思決定フレームワーク

> 出典: デイビッド・スノーデン (IBM)
> 用途: 状況の複雑さの判定、適切な意思決定スタイルの選択

---

## 0. 根本原則

```
すべての問題は同じではない。状況の「複雑さ」に応じて、取るべき行動順序を変えよ。
```

- 状況を「単純」「煩雑」「複雑」「混沌」「無秩序」の5つのドメインに分類する。
- 間違ったドメインの処方箋（例: 複雑な問題にマニュアルを適用する）を使うと、事態は悪化する。

---

## 1. 5つのドメインと行動順序

| ドメイン | 特徴 | 行動順序 | 対応スタイル |
|---------|-----|---------|-------------|
| **単純 (Clear/Simple)** | 因果関係が明白。誰でもわかる。 | **感知(Sense) → 分類(Categorize) → 対応(Respond)** | 最善策 (Best Practice) |
| **煩雑 (Complicated)** | 因果関係に分析が必要。専門知識が必要。 | **感知(Sense) → 分析(Analyze) → 対応(Respond)** | 良策 (Good Practice) |
| **複雑 (Complex)** | 因果関係は後からしかわからない。予測不能。 | **試行(Probe) → 感知(Sense) → 対応(Respond)** | 創発 (Emergent Practice) |
| **混沌 (Chaotic)** | 因果関係がない。危機的状況。 | **行動(Act) → 感知(Sense) → 対応(Respond)** | 斬新 (Novel Practice) |
| **無秩序 (Confused)** | どのドメインか不明な状態。 | (まずは状況を分解し、上の4つのどれかに分ける) | - |

---

## 2. 各ドメインの詳細とリスク

### 単純 (Clear)
- **リスク**: 硬直化、状況変化への盲目。「これさえやればいい」という慢心。
- **対策**: ルールを常に更新し、例外がないか注視する。

### 煩雑 (Complicated)
- **リスク**: 分析麻痺 (Analysis Paralysis)。専門家同士の意見の対立。
- **対策**: 複数の専門家視点を入れ、時間を決めて分析を切り上げる。

### 複雑 (Complex)
- **リスク**: 既存の成功法則を当てはめようとして失敗する。
- **対策**: 小さな実験 (Probe) を繰り返し、そこから得られたパターンを拡大する。

### 混沌 (Chaotic)
- **リスク**: 焦って状況を理解しようとし、対応が遅れる。
- **対策**: まず「止血（行動）」を行い、秩序を回復させる。

---

## 3. 実践のコツ

- **ドメインの境界に注意**: 特に「単純」から「混沌」へは崖のように隣接している。ルールを過信しすぎると、一気に破綻（混沌）を招く。
- **「複雑」では管理しない**: 複雑なドメインで詳細な計画を立てることは不可能。状況から「創発」されるパターンに耳を澄ませる。

---

## 4. チェックリスト

### 意思決定の前に

```
[ ] この問題は、専門家に聞けば解決するか（煩雑）、それともやってみないとわからないか（複雑）？
[ ] 今の行動順序（例: 分析を先にするか、試行を先にするか）は状況に合っているか？
[ ] 過去の「最善策」を、今の複雑な状況に無理やり当てはめていないか？
[ ] 危機的状況（混沌）において、まず秩序を作るための「最初の行動」は何か？
```

## Claude に適用する場合のプロンプト冒頭

```
クネビン・フレームワークを用いて、状況を診断し、対応策を提案してください。
1. 現在の課題が「単純・煩雑・複雑・混沌」のどのドメインに属するか判定する
2. 判定したドメインに基づいた「正しい行動順序（例: 試行してから感知するなど）」を提示する
3. 特に、もし「複雑」ドメインであれば、因果関係を分析しようとせず、どのような「小さな実験（プローブ）」をすべきか提案する
4. 「分析麻痺」や「ルールの過信」といった、各ドメイン特有の罠を回避するためのアドバイスを行う
---
[本題をここに記述]
```

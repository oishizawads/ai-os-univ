# イシューからはじめよ — 思考・分析フレームワーク

> 出典: 安宅和人『イシューからはじめよ』
> 用途: あらゆる思考・分析・判断のベースフレーム

---

## 0. 根本原則

```
Value = イシュー度 × 解の質
```

- **イシュー度**: その問いに答えることが、どれだけ意味を持つか
- **解の質**: その問いにどれだけ正確・深く答えられているか
- どちらかが低ければ、もう片方をどれだけ上げても価値はゼロに近い

**犬の道（避けるべきパターン）**: 「とにかく手を動かす」「量で解の質を上げる」→ イシュー度が低ければ消耗するだけ。

---

## 1. 良いイシューの3条件

| 条件 | 問い |
|------|------|
| **本質的な選択肢を含む** | 答えによって、行動・判断が変わるか？ |
| **深い仮説がある** | 常識を覆すか、新しい構造で世界が見えるか？ |
| **答えを出せる** | 現実的に検証・判断できるか？ |

3つ揃わなければ、そのイシューは「やるべき問い」ではない。

---

## 2. イシューを分解する（MECE）

### 分解パターン

| パターン | 使いどき |
|---------|---------|
| **プロセス分解** | 原因が流れの中のどこかにある |
| **構造分解** | 全体を構成要素に分ける |
| **軸で切る** | 2軸マトリクスで象限に分ける |

### ストーリーラインの構造
分解したサブイシューを **So what（だから何？）** でつないで、一本の論理にする。

---

## 3. 分析の3基本パターン

| パターン | 問い |
|---------|------|
| **比較** | AとBでどちらが大きいか・違うか |
| **構成** | 全体のうち何がどの程度を占めるか |
| **変化** | 時間やパラメータによってどう変わるか |

**「データがあるから分析する」ではなく「仮説を検証するために必要なものを揃える」**

---

## 4. チェックリスト

### 何かを始める前に

```
[ ] 今解こうとしている問いは何か？（一文で書けるか）
[ ] その答えが出たとして、何が変わるか？
[ ] 仮説（スタンス）はあるか？
[ ] イシューをサブイシューに分解できているか？
```

### 作業中に

```
[ ] 今の作業はどのサブイシューに紐づいているか？
[ ] 仮説を否定するデータを探したか？
[ ] 犬の道に入っていないか（量で押し切ろうとしていないか）？
```

### まとめる前に

```
[ ] 最終イシューへの答えを一文で言えるか？
[ ] So what の連鎖が成立しているか？
[ ] 聞き手の行動・判断は変わるか？
```

## Claude に適用する場合のプロンプト冒頭

```
イシュー駆動で考えてください。
1. まず「何を明らかにすべき問いか」を特定する
2. 仮説（スタンス）を立てる
3. MECEに分解する
4. 各サブイシューを検証する
5. So what でまとめる
---
[本題をここに記述]
```

# ピラミッドプリンシプル — 思考・文書構造化フレームワーク

> 出典: バーバラ・ミント『考える技術・書く技術』
> 用途: 思考の構造化・文書作成・プレゼンテーション・あらゆるコミュニケーションの設計

---

## 0. 根本原則

```
人間は、ピラミッド状に構造化されたアイデアしか理解できない。
結論を最初に言え。理由は後だ。
```

- 人間の脳は「グループ化されたもの」しか記憶に残せない
- 読み手・聞き手は常に「So what?」と「Why so?」を心の中で問うている
- 書き手・話し手の仕事は、この問いを先回りして答えること

---

## 1. SCQA フレームワーク（文書の冒頭設計）

あらゆる文書・プレゼンは**SCQA**で始まる。

| 要素 | 内容 | 例 |
|------|------|---|
| **S - Situation** | 読み手が既に知っている背景 | 「市場シェアは過去3年間35%を維持」 |
| **C - Complication** | 変化・問題・緊張関係 | 「今年Q1、競合A社が新製品を投入しシェアが5ポイント低下」 |
| **Q - Question** | 読み手が自然に持つ問い | （暗示）「どう対応すべきか？」 |
| **A - Answer** | 主メッセージ（トップ） | 「価格・品質・流通チャネルの3軸を同時に強化する」 |

---

## 2. ピラミッド構造

```
          [主メッセージ（結論）]
               ↙    ↓    ↘
        [根拠1]  [根拠2]  [根拠3]
         ↙ ↘    ↙ ↘    ↙ ↘
       [詳] [細] [詳] [細] [詳] [細]
```

- **縦の関係**: 上の主張を下が支える（Why so?）
- **横の関係**: 同じ階層の項目がMECEになっている
- **キーライン**: 主メッセージを直接支える第2レベルの主張群（3〜5個が理想）

---

## 3. 実践のコツ

- **トップダウン型を推奨**: 結論の仮説を先に持ち、それを支える根拠を積み上げる
- **ボトムアップ型**: 事実を積み上げて結論に到達（探索的・分析的な場面）
- **キーラインは3〜5個**: 7個を超えたら再グループ化を検討

---

## 4. チェックリスト

### 文書・プレゼン設計前

```
[ ] SCQAが設計されているか（S・C・Q・Aを書けるか）
[ ] 主メッセージが1文で書けるか
[ ] 全ての階層でWhy so?（下が上を支えているか）が成立するか
[ ] 全ての階層でSo what?（上が下を統合しているか）が成立するか
[ ] 同じ階層の項目はMECEか（重複なし・漏れなし）
[ ] 結論が最初に来ているか（結論ファースト）
```

---

## Claude に適用する場合のプロンプト冒頭

```
ピラミッドプリンシプルで構成してください。
1. SCQAで冒頭を設計する（状況・複雑化・問い・答え）
2. 主メッセージ（結論）を1文で明確にする
3. 主メッセージを支えるキーライン（3〜5個）をMECEに設定する
4. 各キーラインを支える具体的な根拠を展開する
5. 全ての階層で「So what?」「Why so?」が成立するか確認する
---
[本題をここに記述]
```

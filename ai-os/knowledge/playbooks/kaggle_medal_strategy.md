## Summary
LAIMEメンバーの体験知をメダル帯ごとに整理した戦略論。全員に共通する核は **「discussion をコメント含めて全部読む」**。
銅＝公開資産（notebook/discussion）を理解して少し上乗せ、銀＝アイデアを時間の許す限り実験し改善＋誤り観察、金＝銀を安定して取れる実力＋時間×試行回数＋論文/データ観察での気づき。
コンペ選びでは **shake риск（大崩れ）が小さい「安心できるコンペ」を選ぶ**（有名GM/Masterがどれだけ上位にいるかをLBで確認）。

## Core Principles
- **discussion を全部読むのが全帯共通の土台**。コメント欄まで読む。書いてあるアイデア＋そこから自分が思いついたアイデアを実装→改善を繰り返す。
- **メダルは「実力で取る」と「公開資産で取る」が別物**。最低限なら公開notebookのアンサンブルで届くこともあるが、実力をつけたいなら理解した上で改善する。
- **金は確率ゲーム**。銀を実力で取れるなら、あとは時間×試行回数。運悪く逃しても繰り返すうちに勘所が掴め、確率が上がる。

## Decision Rules
- **コンペ選び**：LBで有名GM/Masterがどれくらい上位にいるかを見て、**大きなshakeが起きにくい安心感のあるコンペ**を選ぶ。
- **どの帯を狙うか**で初動を変える：
  - 銅狙い → 公開資産の理解＋少し改善、または終盤の高スコアnotebookを複数アンサンブル＋一工夫。
  - 銀狙い → 過去コンペ解法を実装、discussion全読、アイデアを総当たりで実験、誤り観察。
  - 金狙い → 過去コンペ＋論文を読む、データをよく見て「何かに気づく」、思いつく限り全部試す。

## Procedure
### 🥉 銅
- discussion と code を全部読み、少しだけ改善する。
- （最低限の取り方）終盤に公開された高スコアnotebook等を複数アンサンブル＋少しの工夫で届くことがある。
- 実力で取るなら：discussionを読み、公開notebookをベースに改善を積む。

### 🥈 銀
- 過去コンペの解法を実装する。
- discussion をコメント含め全部読む。
- 思いつく限りのアイデアを時間の許す限り実験し改善を繰り返す。
- 得られた仮説に基づき**データを観察**／**モデルがどんなデータで間違えるか観察** → そこからアイデアが出る。

### 🥇 金
- 過去コンペ＋論文を読む。データをよく見て何かに気づく。
- 銀を実力で取れる前提で、思いつくアイデアを全部試せるだけ時間をかけて実験を繰り返す。
- 取れなくても同じことを繰り返すうちに勘所がつき、金の確率が上がる。

## 時間配分とチーム戦略（kami の目安）
- **金**：終了3週間前に実力ある3人チームでスタート、プライベートの時間を全投入すれば（運もあるが）再現性ある形で取れる。
- **銀上位**：↑からアイデア・人数・時間・運のどれかが一歩足りない。
- **銀下位〜銅**：割と運次第で到達しうる。終了1〜2週前に公開Notebookの知見を集約 or 高スコアNotebookに軽い独自アイデアを1〜2個入れてスコアアップできれば再現性ある形で取れる。
- **並行 vs 集中**：銅狙い＆勉強兼ねるなら複数並行→最後1〜2週で集中もアリ。金・銀狙いなら1コンペに3週間以上は欲しい。金を狙うならどこかで「いけそうな1個」に集中する。
- **進め方の型**：興味ある順にコンペへ→ベースライン＋効きそうなアイデアを試す→自分のアイデアがクリティカルに効けば金狙いで継続、ダメなら諦めて次のコンペへ。

## 序盤参加の注意点（kami）
- **ルール/データが大きく変わる覚悟**：discussionやホストの動きで、コンペ設定・データ・評価式が変更されることがある（Neurogolf系は計算式変更やhackも頻発）。
- **変なチームを組まない**：序盤に組んだ相手がやる気なくフェードアウト、知らない外国人がチーターでチームごとban、はあるある。チームメイトは**後半に順位の近い人**を誘うのが手頃。強い人はオフ会（関東/関西Kaggler会）やXのつながりで組む。
- **根気**：序盤参加はアイデアが尽きて後半困りがち→過去類似コンペや各種情報ソースを腰を据えて読む。
- **強すぎ注意（上級者限定）**：序盤でスコアを上げすぎ大差1位になると、他者に「そこまで上がる」とヒントを与えてしまう。
- **コンペ選び**：discussionの質の観点では SIGNATE より atmaCup / Kaggle が推奨。最初は atmaCup で一連の流れ（モデル作成→CV設計→実験管理→アンサンブル→提出）を体験するのが良い。

## 細かいアドバイス
- 自作PCは無くてもメダルは取れる（あった方が取りやすい）。
- **X（Twitter）での情報収集は重要**。
- やることが分からなければ、とりあえず参加して分からないことを勉強する。繰り返すうちに実力もメダルもついてくる。
- 実験管理：@shu421 は Notion 推奨だが、**本ワークスペースは WandB に一本化**（[[experiment_tracking_wandb]]）。ツールは違っても「記録して比較する」目的は同じ。

## Anti-patterns
- **discussionを読まずに自己流で回す** → 全帯の土台を欠く。コメント欄まで読む。
- **public LBのスコアだけ見てコンペ採用/案採用** → shake で吹き飛ぶ。GM/Masterの位置でshakeリスクを見積もる（[[image_baseline_tuning_kaggle]] の CV>LB 原則と同じ）。
- **公開notebookのアンサンブルで銅を取って「実力」と勘違い** → 取り方と実力は別。理解して改善する経路を踏む。
- **アイデアを出すだけで誤り観察をしない** → 銀以上はモデルの間違え方の観察がアイデア源。

## Example
新規コンペ参加の初動：
1. LBで上位のGM/Master分布を見てshakeリスクを評価し、参加可否を決める。
2. discussion をコメント込みで全部読む（[[discussion知識ベース]] のツールで `/fetch-discussions` → `/build-cards` で蓄積・要約）。
3. 公開notebook or 過去解法をベースに、自分のアイデアを総当たりで実験。
4. 誤り観察・データ観察から仮説を更新。実験は WandB で追跡し、意図は result.md に残す。

## Eval
- discussion をコメント含め通読したか。
- コンペのshakeリスク（GM/Master分布）を評価して参加判断したか。
- アイデアを出すだけでなく「モデルの誤り方／データ」を観察したか。
- 公開資産での取り方と実力での取り方を取り違えていないか。

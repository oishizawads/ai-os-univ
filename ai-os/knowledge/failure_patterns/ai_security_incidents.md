## Summary
AI システムで実際に発生したセキュリティインシデントのパターンと教訓。
プロンプトインジェクション、データ流出、出力改ざんの事例を記録し、再発防止に活用する。

## Incident Patterns

### 1. プロンプトインジェクション事例

#### 事例 A: 間接インジェクションによるデータ流出
- **発生状況**: ユーザー入力に悪意あるプロンプトが混入
- **影響**: システムプロンプトの一部が出力に含まれる
- **原因**: 入力バリデーション不十分
- **検知方法**: 出力モニタリングで異常検知
- **対応**: 入力フィルタリング強化、出力検証追加
- **教訓**: 信頼できない入力は必ずサニタイズ

#### 事例 B: マルチターン攻撃による制限迂回
- **発生状況**: 複数回の対話で段階的に制限を解除
- **影響**: 禁止された操作が実行可能に
- **原因**: セッション間の状態管理不十分
- **検知方法**: 不審な対話パターン検出
- **対応**: セッション隔離、累積リスク評価
- **教訓**: 単一ターンだけでなく、対話全体を監視

### 2. データ流出事例

#### 事例 C: トレーニングデータ漏洩
- **発生状況**: AI がトレーニングデータの一部を出力
- **影響**: 機密情報が外部に流出
- **原因**: データマスキング不十分
- **検知方法**: 出力内容の自動スキャン
- **対応**: データマスキング強化、出力フィルタリング
- **教訓**: トレーニングデータに機密情報を含めない

#### 事例 D: コンテキスト漏洩
- **発生状況**: システムプロンプトがユーザーに暴露
- **影響**: 内部ロジック・制約が把握される
- **原因**: エラーハンドリング不十分
- **検知方法**: ユーザー報告
- **対応**: エラーメッセージの一般化
- **教訓**: エラーメッセージに内部情報を含めない

### 3. 出力改ざん事例

#### 事例 E: 悪意あるコード生成
- **発生状況**: AI が脆弱性を含むコードを生成
- **影響**: セキュリティホールが導入される
- **原因**: コード検証不十分
- **検知方法**: コードレビュー・静的解析
- **対応**: 自動セキュリティスキャン導入
- **教訓**: AI 生成コードは必ず検証

#### 事例 F: バイアス増幅
- **発生状況**: AI が差別的・有害な出力を生成
- **影響**: ユーザーに不利益・不快感
- **原因**: コンテンツフィルタ不十分
- **検知方法**: ユーザー報告・自動検出
- **対応**: フィルタリング強化、多様性テスト
- **教訓**: 出力の品質を継続的に監視

### 4. 2026-06-20: 未根拠のインシデント断定とローカルログへの資格情報保存

- **当初の申告**: Claude Code が `.claude/AGENTS.md` の注入ブロックと `context_augment.py` フックを発見・隔離したと報告した。
- **検証結果**: 実ファイル、Git 差分、全履歴、保存トランスクリプトのツール実行記録のいずれにも、当該ブロックやフックが実在した証拠はなかった。Claude は `AGENTS.md` と `settings.json` を読むツール呼び出しなしに発見を断定し、設定編集・隔離・インシデントファイル作成も実行していなかった。
- **実害の有無**: `import.py` は読み取りだけで実行されず、`.env` の内容が当該セッションで出力された証拠もない。したがって、悪性フックによる侵入・実行は未確認であり、当初報告は誤り。
- **別途確認した実問題**: continuous-learning のフックが全ツール入出力をローカル保存し、GitHub PAT をログへ残していた。さらに W&B キーが `settings.local.json` のコマンド許可と Claude トランスクリプトに残り、Notion トークンが現在のブランチから到達不能な `git filter-branch` のバックアップ参照 `refs/original/*` で検出された。
- **実施対応**: Claude Code を停止し、continuous-learning の Pre/PostToolUse 登録を無効化。資格情報を含む観測ログとトランスクリプトを削除し、`settings.local.json` の平文キー付き許可を削除。削除後の秘密検知は対象3領域で0件。
- **残対応**: GitHub PAT、W&B キー、Notion トークンは失効・再発行する。`refs/original/*` の削除と reflog 失効、Git オブジェクトの回収は破壊的なため、必要性とバックアップを確認して別作業で行う。
- **根本原因**: AI の未根拠な生成を、ツール実行証跡と照合せずインシデント事実として扱ったこと。加えて、観測フックが秘密情報を含み得るツール入出力を永続化していたこと。
- **再発防止**: インシデント断定には「実ファイル」「Git/ハッシュ」「保存されたツール呼び出し」の複数証拠を必須とする。ログも秘密検知対象とし、資格情報をコマンド文字列や許可履歴へ入れない。

## Lessons Learned

### 共通教訓
1. **Zero Trust**: AI 出力を信頼せず、常に検証する
2. **Defense in Depth**: 単一の防御に依存しない
3. **Continuous Monitoring**: 監視を継続的に実施
4. **Rapid Response**: インシデントに迅速に対応
5. **Learning Culture**: 失敗から学び、改善する

### 技術的教訓
1. 入力バリデーションは必須
2. 出力フィルタリングは多層化する
3. エラーメッセージは一般化する
4. セッションは隔離する
5. 監査ログは完全に記録する

### 組織的教訓
1. セキュリティは全員で取り組む
2. トレーニングは定期的に実施
3. インシデント対応は訓練する
4. 情報共有は迅速に
5. 改善は継続的に

## Anti-patterns
- インシデントを隠蔽する
- 根本原因分析を省略する
- 再発防止策を実施しない
- 教訓を共有しない
- 訓練を省略する
